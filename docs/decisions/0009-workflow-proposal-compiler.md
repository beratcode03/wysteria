# 9. Workflow Proposal Compiler Boundary

Date: 2026-09-11

## Status

Accepted

## Context

Wysteria operates on strict, typed declarative Workflow IR. However, workflows are frequently generated by unconstrained external systems such as Large Language Models (LLMs) or humans using visual IDEs. These raw "proposals" often lack deterministic canonicalization, explicit typing, or compliance with structural limits. 

Passing raw LLM output directly into the core validation engine conflates untrusted generation with trusted evaluation and makes it harder to trace the provenance of a workflow ("Where did this come from?").

## Decision

We are introducing a **first-class Compiler Boundary** for untrusted proposals. Wysteria now defines a distinct `WorkflowProposal` model, separate from `Workflow` IR.

The compiler acts as the boundary guard:
1. **Model separation**: `WorkflowProposal` != `Workflow`. Proposals specify intent and source provenance but contain untrusted raw workflow data.
2. **Deterministic Compilation**: The compiler takes a `WorkflowProposal` and deterministically parses, normalizes, and constructs a strict `Workflow` IR model.
3. **Structured Diagnostics**: Compilation failures (e.g. unknown nodes, missing types) yield deterministic structured diagnostics rather than raw exceptions.
4. **Provenance**: The source of the proposal (`human`, `llm`, `ide`) and its fingerprint are preserved in Wysteria's downstream CI artifacts and reporting.
5. **No execution**: The compiler performs purely structural analysis and never executes arbitrary code. Wysteria remains an LLM-free trusted evaluation core; it defines the `ProposalSource` API boundary, but any hosted LLM adapter remains outside the core.

## Consequences

- The `wysteria compile` CLI command allows deterministic verification of LLM proposals before they are executed.
- Downstream systems can explicitly log that a verified contract was generated by an LLM via the `ProposalSource` provenance field.
- The Wysteria trusted core is protected from malicious or oversized LLM generations via the safe compiler parser limits.
